### Atom Type and Chemical Component Definitions
AlphaFold 3 manages detailed definitions of common atom types for proteins and nucleic acids, along with structured mappings and fixed-size atom representations to ensure consistent identification and data storage during molecular modeling. This includes the comprehensive handling of Chemical Components Dictionary (CCD) data through a dedicated [`Ccd`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L46) class and [`ComponentInfo`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L117) dataclass, which incorporate efficient processing and caching mechanisms.

The system defines various atom type constants in [`/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py), such as [`RESIDUE_ATOMS`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py#L102) (a mapping of residue names to their constituent atoms) and [`PROTEIN_BACKBONE_ATOMS`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py#L127). Specialized fixed-size atom representations like [`ATOM37`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py#L143) (for 37 common protein atom types) and [`ATOM14`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py#L154) (a more compact representation) are used to standardize atom data storage, particularly in contexts where all residues need to be padded to a uniform size. Similarly, [`ATOM29`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py#L253) provides a fixed-size representation for nucleic acid atom types. The system also accounts for protonation states through [`PROTONATION_HYDROGENS`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/atom_types.py#L264), which identifies hydrogen atoms whose presence is dependent on a residue's protonation.

For chemical component management, the [`Ccd`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L46) class, defined in [`/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py), serves as the primary interface for accessing Chemical Components Dictionary (CCD) information. It loads CCD data from a pre-processed pickle file and supports user-provided custom CCD entries for overrides or extensions. The [`ComponentInfo`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L117) dataclass provides a structured and type-safe representation of chemical component data, including properties like name, type, formula, and SMILES. Functions like [`mmcif_to_info`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L128) parse raw mmCIF data into [`ComponentInfo`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L117) objects, while [`component_name_to_info`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L183) retrieves [`ComponentInfo`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L117) for a given residue name. Caching mechanisms, such as those applied to [`_load_ccd_pickle_cached`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L38) and [`component_name_to_info`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L183), optimize performance by avoiding redundant data loading and processing. The system also includes utilities, like [`type_symbol`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L190), to determine the element type of a specific atom within a chemical component.

Additionally, [`/google-deepmind/alphafold3/src/alphafold3/constants/chemical_component_sets.py`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_component_sets.py) manages predefined sets of chemical components, categorizing ligands and crystallization aids. These sets, such as [`GLYCAN_LINKING_LIGANDS`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_component_sets.py#L36) and [`COMMON_CRYSTALLIZATION_AIDS`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_component_sets.py#L43), are loaded from a pickled data file, ensuring immutability for data integrity. The generation and processing of these chemical component data sets are handled by scripts within [`/google-deepmind/alphafold3/src/alphafold3/constants/converters`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/converters), which convert raw CCD CIF files into pickled Python objects and further categorize them into specific sets, utilizing secure data handling through [`safe_pickle`](https://github.com/google-deepmind/alphafold3/src/alphafold3/constants/chemical_components.py#L28). See [Secure Data Loading with Restricted Pickle](#common-utilities-and-constants-secure-data-loading-with-restricted-pickle) for more details on secure data handling.
