### Haiku Modules and Optimization Utilities
AlphaFold 3 leverages a suite of custom Haiku modules and optimization utilities to enhance numerical stability, manage memory, and improve computational efficiency, particularly in the context of mixed-precision training and large-scale JAX computations.

Core Haiku modules are customized to address the specific demands of molecular modeling. For instance, the [`LayerNorm`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/haiku_modules.py#L50) module ([`/google-deepmind/alphafold3/src/alphafold3/model/components/haiku_modules.py`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/haiku_modules.py)) incorporates an [`upcast`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/haiku_modules.py#L53) option, which temporarily promotes lower-precision inputs (e.g., [`bfloat16`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/model_config.py#L34), [`float16`](https://github.com/google-deepmind/alphafold3/docs/output.md#L25)) to [`float32`](https://github.com/google-deepmind/alphafold3/run_alphafold.py#L505) during normalization to prevent numerical instability, then casts them back. Similarly, the [`Linear`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/haiku_modules.py#L197) module ([`/google-deepmind/alphafold3/src/alphafold3/model/components/haiku_modules.py`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/haiku_modules.py)) is designed for flexibility, supporting arbitrary input tensor ranks, configurable weight initializers, and an option to transpose weights for memory optimization on accelerators like TPUs. It also includes an optimized path for scalar inputs, bypassing [`jnp.einsum`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/network/modules.py#L123) for improved efficiency.

Memory management and throughput optimization for large datasets are critical, leading to the development of sharded mapping utilities. The [`sharded_map`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/mapping.py#L64) and [`sharded_apply`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/mapping.py#L106) functions ([`/google-deepmind/alphafold3/src/alphafold3/model/components/mapping.py`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/mapping.py)) enable the processing of large batches of data by dividing them into smaller, manageable "shards." This approach prevents out-of-memory errors by applying operations to chunks of data sequentially and then reassembling the results. This sharding mechanism is particularly useful for inference with large batches, where the [`inference_subbatch`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/mapping.py#L226) function can split arguments into sub-batches, process each, and concatenate the outputs.

Beyond core modules and sharding, a set of general utilities ([`/google-deepmind/alphafold3/src/alphafold3/model/components/utils.py`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/utils.py)) supports data processing. This includes [`remove_invalidly_typed_feats`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/utils.py#L35) for filtering features to ensure compatibility with hardware accelerators, and a [`bfloat16_context`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/utils.py#L55) manager which, in conjunction with [`bfloat16_getter`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/utils.py#L46), ensures that Haiku parameters intended for [`jnp.bfloat16`](https://github.com/google-deepmind/alphafold3/run_alphafold.py#L505) are correctly typed during initialization. The [`mask_mean`](https://github.com/google-deepmind/alphafold3/src/alphafold3/model/components/utils.py#L60) function provides a robust way to compute the mean of an array while accounting for a mask, handling broadcasting and preventing division by zero, which is essential for various masked computations within the model.
