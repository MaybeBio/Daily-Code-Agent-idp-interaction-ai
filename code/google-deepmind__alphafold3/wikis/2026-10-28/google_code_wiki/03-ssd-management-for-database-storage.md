### SSD Management for Database Storage
The AlphaFold 3 environment includes scripts to manage Solid State Drives (SSDs) for database storage, particularly within cloud environments such as Google Cloud Platform (GCP). These scripts facilitate the mounting, formatting, and efficient transfer of large public database files, while also addressing space constraints and prioritizing file transfers.

The primary script for configuring SSDs is [`/google-deepmind/alphafold3/src/alphafold3/scripts/gcp_mount_ssd.sh`](https://github.com/google-deepmind/alphafold3/src/alphafold3/scripts/gcp_mount_ssd.sh). This script automates the process of identifying, formatting, and mounting the first available unmounted SSD to a specified directory, which defaults to [`/mnt/disks/ssd`](https://github.com/google-deepmind/alphafold3/docs/installation.md#L258). It ensures idempotency, meaning it can be run multiple times without causing unintended side effects, by checking if the target mount directory is already in use. When formatting an SSD, it uses [`mkfs.ext4`](https://github.com/google-deepmind/alphafold3/src/alphafold3/scripts/gcp_mount_ssd.sh#L35) with options to enhance performance and manage disk space efficiently.

For transferring public database files, the [`/google-deepmind/alphafold3/src/alphafold3/scripts/copy_to_ssd.sh`](https://github.com/google-deepmind/alphafold3/src/alphafold3/scripts/copy_to_ssd.sh) script is utilized. This script copies a predefined list of database files from a source to a target SSD directory. It incorporates logic to handle scenarios where the available SSD space is limited. By calculating the total size of the selected files and comparing it against the available space, the script can iteratively adjust the list of files to be copied, prioritizing certain files and logging any that could not be accommodated due to insufficient space. This mechanism ensures that critical database components are transferred first, making efficient use of available storage.
