# Feature: Built-in RESP Charges and Sulfonate Parameters <!-- rq-0169651d -->

Trusted charges for the systems the group has derived by hand, shipped with the package, so they
are used without DFT or charge files. They come from RESP fits of separate fragments: the
methacrylate (acrylate, acrylamide) linker, the cation (N⁺ and its four carbons) and the anion; the
rest of the monomer keeps the force field's charges.

## Data <!-- rq-cfd68d9b -->

`forcefield/data/builtin_charges.yaml`, version 1:

- `monomers` / `initiators`: name → `{scale_of_source, atoms}`. `atoms` maps the software's atom
  names (the same in the F, R and E residues; for initiators the head/tail residue) to a charge, or
  to `{charge, H}` for an atom and its hydrogens, like a charge file. The values are **unscaled**
  (`scale_of_source` records the factor the source topology used, e.g. 0.85, so the source is
  reproduced with `CHARGE_SCALE = 0.85`).
- At the time of writing: `DMAPS` (ester, cation, anion; from the group's OPLS-AA topology) and
  `KPS` (SO4⁻ end group: the O bonded to the chain, S and three O). `A3361` and `A3367` are added
  when their values are available.

## Use <!-- rq-12b17c91 -->

- `parametrize(..., builtin_charges=True)`; input key `BUILTIN_CHARGES = yes | no` (default yes)
  for `build`, `bulk`, `slab`, with any force field.
- For every residue of a listed monomer or initiator, the listed atoms take these charges and stay
  fixed; the other atoms keep the backbone's force-field charges and absorb the balance, so the
  residue keeps its integer charge. Residues covered by DFT charges (`DFT`) do not use them; a user
  `CHARGES` file overrides single atoms on top.
- **Spacer variants** (`SPACER = n`, n ≥ 2, e.g. `DMAPS-sp4`) use their parent's built-in charges:
  each connected group of listed atoms (linker, cation, anion) is found in the variant by element,
  H count, heavy-atom degree and formal charge, and keeps its values; the added (or removed) spacer
  CH2 keeps the force field's charges, as in the source scheme. N-alkyl variants (`ALKYL`) and
  `SPACER = 1` (the cation and anion groups touch) do not.
- Then `CHARGE_SCALE` applies as usual.
- The build summary lists `built-in RESP charges: DMAPS, KPS`; `Topology.builtin_blocks` lists the
  residues.

## Built-in Bonded Terms (OPLS-AA): Values on Each Bonded Line <!-- rq-7b2aba9e -->

The stock OPLS-AA atom types are kept everywhere (the sulfate of KPS is `opls_467` / `opls_493` /
`opls_494`, like the sulfonate). Terms that need values the force field does not have are written
**with their values on the bonded line** of the `[ bonds ]`, `[ angles ]` and `[ dihedrals ]`
sections of the `.top` / `.itp` (and of the `.rtp`), e.g. `37 38 1 0.181 185769.6`. This is plain
GROMACS and works with every version; `ffbonded.itp` keeps only the force field's own terms.

- **Sulfonate** (`forcefield/data/oplsaa_params.yaml`, the group's values), for the terms the force
  field lacks:

| Term | Types | Value |
|---|---|---|
| bond | CT–SY2 | b0 0.18100 nm, kb 185769.6 |
| bond | OY–SY2 | b0 0.14577 nm, kb 443504 |
| angle | CT–CT–SY2 | 114.70°, 418.400 |
| angle | HC–CT–SY2 | 109.50°, 292.880 |
| angle | CT–SY2–OY | 108.90°, 619.232 |
| angle | OY–SY2–OY | 113.83°, 418.400 |

- **Sulfate end groups** (C–O–SO3⁻ of KPS, APS, NaPS): **every** bond, angle and dihedral that
  contains a sulfate atom takes **GAFF2** values (`forcefield/data/gaff2_so4.yaml`, generated by
  `devtools/extract_gaff2_so4.py` from AmberTools' `gaff2.dat`, GROMACS units). The sulfate atoms are
  the GAFF2 types s6 (S), o (the three terminal O), os (the O bonded to the chain); their neighbours
  map from their OPLS bonded type (`CT`→c3, `HC`→hc, `C_2`/`C`→c, `CA`→ca, `O_2`/`O`→o, `OS`→os,
  `N`→n). Dihedrals use GAFF2's specific entry or its `X` wildcard one and are converted to
  Ryckaert-Bellemans (Σ k (1 + cos(nφ − γ)), γ = 0 or 180°, cos nφ by Chebyshev polynomials,
  ψ = φ − 180°). A term not found stays a missing parameter.
- `Topology.explicit` maps a term's atom indices to the values written on its line; the build
  summary gives their number. A user `PARAMS` file fills the force-field tables as before.
- Charges are not affected (the built-in RESP charges).
